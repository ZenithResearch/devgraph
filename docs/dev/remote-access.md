# Remote command adapter — draft

**Status: draft library adapter; not deployed remote access.**

`devgraph.remote.RemoteGateway` validates four Issue commands, calls the existing
Python HTTP client, and projects its response into a small output allowlist.
It requires an injected client/transport and an explicit opaque credential.
It does not start a listener, expose a public endpoint, or implement a tunnel,
relay, webhook, Matrix, or other external transport.

Reads can use the existing read authority boundary. **The local read credential
remains read-only.** The mutation flow demonstrated here uses synthetic legacy
bearer credentials in an in-memory test fixture; it does not implement current
signed writes. Signed-write adoption is an explicit draft blocker for production
remote mutations. The separately packaged [agent integrations](../user/agent-integrations.md)
do not turn this library into a remotely deployed service.

## Supported commands

The envelope has exactly `operation` and `arguments`. Unknown fields, nested
authority objects, transport metadata, and unsupported commands are rejected.
The credential is a separate `dispatch(payload, credential=...)` argument; it
does not belong in the command JSON. An external adapter must extract the
command without forwarding its raw transport event or treating a transport
sender identity as Devgraph authority.

| Command | Arguments | Successful projection |
| --- | --- | --- |
| `create_issue` | `work_id`, `title`, `idempotency_key` | Accepted receipt metadata; synthetic mutation proof only. |
| `get_issue` | `work_id` | Presence (`found`), without the Issue body. |
| `list_issues` | Optional `include_archived` boolean, default `false` | Count of the returned page, bounded to 0–50. |
| `transition_issue_to_review` | `work_id`, `idempotency_key` | Accepted receipt metadata; synthetic mutation proof only. |

The adapter does not expose arbitrary Work kinds, a query language, document
content, or a generic client method. Listing has no pagination arguments: its
count is not the total graph size. For complete record reads or other supported
operations, use the [Python client contract](../client-adapter-contract.md) and
[current API](../api.md).

These four payloads are synthetic examples for the in-process tests below;
the mutation examples are not production write instructions:

```json
{
  "operation": "create_issue",
  "arguments": {
    "work_id": "remote-example-issue",
    "title": "Synthetic remote example",
    "idempotency_key": "remote-example-create"
  }
}
```

```json
{
  "operation": "get_issue",
  "arguments": {"work_id": "remote-example-issue"}
}
```

```json
{
  "operation": "list_issues",
  "arguments": {"include_archived": false}
}
```

```json
{
  "operation": "transition_issue_to_review",
  "arguments": {
    "work_id": "remote-example-issue",
    "idempotency_key": "remote-example-review"
  }
}
```

Work IDs use the shared Work ID validator. Titles are 1–512 UTF-8 bytes;
legacy idempotency keys are 1–256 UTF-8 bytes; credentials are 1–4096 UTF-8
bytes. Those text fields reject ASCII control characters. The request ID is
generated by the gateway, matches `rmt_[a-z2-7]{26}`, and never supplies
idempotency or authority.

## Authority and output boundary

1. An external caller supplies only the strict command envelope and an explicit
   credential. Transport metadata remains outside Devgraph.
2. The gateway validates both inputs, creates `DevgraphRequestContext`, and
   forwards the credential through `DevgraphHttpClient` to the existing API.
3. `CredentialVerifier.verify(credential, audience=...)` derives authority;
   the gateway does not construct `AuthorityContext` or accept caller-selected
   actors, sessions, scopes, or authority correlation IDs.
4. The existing API, authorization, audit, idempotency, outbox, and client
   response validation apply. There is no trusted-localhost exception or
   parallel authority path.
5. `TransportSafeProjector` emits only the fields below. Callers should serialize
   that projection, not client models, raw responses, or caught exceptions.

`RemoteIngressCredential` is a bounded opaque holder, not a general Pydantic
model. Its supported validation entry points are construction, `model_validate`,
and `model_validate_json`; rejected credentials raise
`RemoteCredentialValidationError` with fixed, input-free structured errors.
The holder omits credential bytes from its representation and dump methods;
generic `TypeAdapter` use and Pydantic model nesting are unsupported. Keep the
opaque credential out of logging even when using these helpers.

| Response model | Complete output field allowlist |
| --- | --- |
| `RemoteFound` | `request_id`, `operation`, `outcome` |
| `RemoteListed` | `request_id`, `operation`, `outcome`, `item_count` |
| `RemoteMutationAccepted` | `request_id`, `operation`, `outcome`, `receipt_id`, `receipt_status`, `duplicate`, `correlation_id` |
| `RemoteProblemResponse` | `request_id`, `operation`, `outcome`, `reason_code`, `status`, `title`, `type`, `correlation_id` |

Reads omit work IDs, titles, descriptions, attachments, and authority identifiers.
Mutation success exposes bounded metadata for an unsigned EventReceipt
operational record, not the mutated Work object.
`pending` means the graph mutation and local EventReceipt committed while the
outbox has not advanced; it does not prove external delivery or a cryptographic
receipt. Correlation IDs are validated before emission; read successes omit them.

Errors use fixed reason codes and public problem text. They do not echo
credentials, idempotency keys, request bodies, raw upstream error details, or
unsafe scalar values. Unknown operations become `unrecognized`; malformed
upstream responses become `malformed_upstream`. A timeout or transport failure
after a mutation has an **unknown outcome**, not proof that nothing changed.
Preserve the original request and idempotency key for any retry.

## Current signed-write incompatibility

The gateway currently dispatches the legacy Issue client wrappers. The current
signed write path instead uses `DevgraphWorkContext`,
`DevgraphHttpClient.execute_named_work`, and `POST /work-operations/v1` with
`X-Devgraph-Work-Authority`. The local read credential cannot authorize either
legacy or named mutations. See [named Work v1](../named-work-v1.md) for the
canonical request and authority contract.

Production remote mutations must remain disabled until the adapter adopts and
tests all of the following together:

- Status changes carry an explicit `expected_version`; the current remote
  transition envelope has no version precondition.
- Named idempotency keys match `[A-Za-z0-9._~-]{16,128}`. The gateway's current
  legacy bound is not interchangeable with that contract.
- Request-bound idempotency preserves the canonical request digest. In the
  synthetic legacy fixture, the same key and operation/resource scope can
  return the prior receipt even when a title changes. That is not a valid
  expectation for named writes: retry the identical request and key after
  uncertainty; a deliberately changed request needs a distinct key.
- The authority system supplies a valid secS projection bound to the request,
  idempotency key, operation, and resources. Wallet signs; secS verifies policy;
  Devgraph verifies the projection. The adapter must not manufacture authority,
  provision a writable bearer token, or substitute a transport identity.

This draft does not prove an external identity binding, remote credential
provisioning, transport replay/rate limits, secure listener configuration, or
native signed-write interoperability. There is no production remote-write or
deployment acceptance claim.

## Reproducible in-process smoke

From the repository root, use a Python environment with the project's runtime
dependencies and `pytest` already installed (see [development checks](../../README.md#development-checks)).
Run:

```bash
PYTHONPATH=src:tests/integration python -m pytest tests/remote tests/integration/test_remote_authority_flow.py tests/integration/test_remote_local_read_boundary.py tests/docs/test_remote_access_contract.py -q
```

This command opens no network listener and needs no secrets, live Devgraph
service, Neo4j, Wallet, secS process, or production configuration. The fixture in
`tests/integration/remote_authority_fixtures.py` uses `MemoryGraphStorage`,
synthetic credentials registered only in `LocalDevVerifier`, FastAPI `TestClient`,
and the real bounded client/gateway. Its `http://testserver` base URL is handled
in-process; it is not a remote host. Do not copy `LocalDevVerifier` provisioning
into a production transport.

`test_remote_local_read_boundary.py` additionally constructs the production
service assembly with memory storage and a temporary generated local read
credential. It proves authorized reads and denied create/review mutations with
no Work, audit, receipt, or outbox changes on denial. It does not contact a live
Neo4j or native authority process.

The focused suite checks:

- Create, get, list, and review transitions through the real client/API with
  synthetic authorization and transactional EventReceipt/outbox behavior.
- Missing, unknown, expired, wrong-audience, wrong-scope, and unavailable-verifier
  denials; denied requests do not reach repository handlers or mutate graph state.
- Strict command validation, fixed error projection, presence/count reads,
  bounded receipt metadata, and malformed upstream response rejection.
- Legacy duplicate/conflict behavior and correlation derived from verified
  authority, rather than a caller's transport metadata.
- These documented examples and output field allowlists against the shipped
  Pydantic command/response contracts.

Passing establishes an in-process library proof only. Record the tested commit
and pytest summary when reviewing this draft; external transport and signed-write
acceptance remain separate work.
